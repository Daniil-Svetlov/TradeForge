# TradeForge

Автоматизированная система торговли криптофьючерсами на BingX: детерминированный торговый бот + ИИ-агент для анализа и отчётов. Сначала инструмент для себя, потом продукт для других.

> ⚠️ Это учебный и исследовательский проект. Не финансовая рекомендация. Торговля фьючерсами с плечом несёт риск потери всего депозита. Любой запуск на реальных деньгах только после проверки на истории и на демо-счёте.

---

## 1. Идея простыми словами

Программа сама торгует по заранее заданным правилам, пока ты занимаешься своими делами:

1. Каждые несколько часов смотрит на цены монет (BTC, ETH, SOL и др.) на BingX.
2. Проверяет правила стратегии (например: «цена пробила максимум за 20 дней и рынок в тренде»).
3. Считает, сколько можно рискнуть (не больше 1-2% депозита на сделку).
4. Открывает сделку и сразу ставит стоп-лосс.
5. Присылает сообщение в Telegram: что сделала, почему, какой риск.

Перед любой торговлей стратегия проверяется на исторических данных. Если на истории она не работает, в бой не идёт.

### Почему именно так

| Решение | Причина |
|---|---|
| Фьючерсы, не бинарные опционы | Честный рынок, известные комиссии, контроль размера позиции и стопов |
| Тренд-стратегия, таймфрейм 4h-1d | Мало сделок, комиссии не съедают прибыль, проще честно проверить |
| Корзина из 5-10 монет | Диверсификация: пока одна монета во флэте, другая может быть в тренде |
| Жёсткое ядро на коде | Детерминированность: одни и те же данные дают одно и то же решение |
| ИИ-агент отдельным слоем | LLM нельзя честно бэктестить и она может ошибаться в числах, поэтому она анализирует и объясняет, но не торгует сама |

## 2. Из чего состоит система

```
         ┌───────────────┐
         │  BingX (API)  │
         └───────┬───────┘
                 │ свечи, ордера, баланс
┌────────────────▼─────────────────┐
│          ЯДРО (код)              │
│  Data → Strategy → Risk → Exec   │  ← все торговые решения здесь
└───────┬───────────────────┬──────┘
        │ сделки, логи      │ лимиты (нельзя обойти)
┌───────▼────────┐   ┌──────▼───────────┐
│  ИИ-агент      │   │ Telegram / Web   │
│ (анализ, отчёты│   │ уведомления,     │
│  новости)      │   │ дашборд          │
└────────────────┘   └──────────────────┘
```

**Модули:**

- **Data**: скачивание и хранение истории свечей.
- **Backtest**: движок проверки стратегий (комиссии, проскальзывание, фандинг, плечо).
- **Strategies**: стратегии, по одному файлу на каждую.
- **Risk**: размер позиции по волатильности (ATR), лимит дневной просадки, лимит плеча, аварийный выключатель (kill switch).
- **Execution**: отправка ордеров, обработка ошибок и обрывов связи.
- **Agent**: ИИ-слой. Читает новости, пишет отчёты, разбирает сделки. Может максимум предложить «не входить в новые сделки», а решение проходит через код с лимитами.
- **Notify**: Telegram-бот.

## 4. Правила безопасности (с первого дня)

- API-ключи BingX: только право **торговли**, **без права вывода**, по возможности с привязкой к IP.
- Ключи хранятся только в `.env`. Файл `.env` обязательно в `.gitignore`.
- Никогда не публиковать ключи в чатах, скриншотах, GitHub.
- В коде: лимит потерь в день, максимум плеча, максимальный размер позиции, kill switch. Эти лимиты агент менять не может.
- Первый запуск только на демо-счёте, потом на минимальной сумме, которую не страшно потерять.

## 5. Подробный план

### Этап 0. Подготовка (1-2 дня)
- [ ] Установить Python (`brew install python`), проверить `python3 --version`
- [ ] Установить VS Code и расширение Python
- [ ] Создать папку проекта и виртуальное окружение (`python3 -m venv venv`)
- [ ] Установить библиотеки: `pip install ccxt pandas`
- [ ] Создать структуру папок и `.gitignore`
- [ ] Завести репозиторий в git (приватный на GitHub)
- [ ] Запустить `test_connection.py` и увидеть свечи BingX

**Результат:** программа получает данные с биржи.

### Этап 1. Данные (1-2 недели)
- [ ] Основы Python: переменные, списки, словари, функции, циклы
- [ ] Основы pandas: таблицы (DataFrame), чтение и запись файлов
- [ ] Загрузчик истории: несколько лет свечей по BTC, ETH, SOL и др.
- [ ] Сохранение в файлы (Parquet или CSV) и проверка данных на пропуски
- [ ] Первый график цены (matplotlib)

**Результат:** локальная база свечей и графики.

### Этап 2. Бэктестер и первая стратегия (3-4 недели)
- [ ] Индикаторы: скользящие средние, ATR, каналы Дончиана
- [ ] Простой бэктест-движок с комиссиями и проскальзыванием
- [ ] Первая стратегия: пробой канала + фильтр тренда
- [ ] Метрики: доходность, максимальная просадка, винрейт, Sharpe, число сделок
- [ ] Учёт фандинга и плеча

**Результат:** отчёт «как стратегия вела бы себя на истории».

### Этап 3. Честная валидация (2-3 недели)
- [ ] Разделение данных: подбор параметров на одном периоде, проверка на другом
- [ ] Walk-forward тест
- [ ] Проверка на других монетах и периодах
- [ ] Проверка устойчивости: небольшое изменение параметров не должно ломать результат
- [ ] Решение: годится стратегия или выбрасываем

**Результат:** стратегия, в которой есть основания верить, либо честный вывод, что edge нет, и поиск следующей идеи.

### Этап 4. Риск и исполнение на демо (3-4 недели)
- [ ] Модуль риска: размер позиции от ATR, лимит риска на сделку, лимит просадки
- [ ] Модуль исполнения: ордера, стоп-лосс, обработка ошибок и обрывов
- [ ] Логирование всех действий
- [ ] Telegram-уведомления
- [ ] Запуск на демо-счёте BingX

**Результат:** бот, который сам торгует на демо.

### Этап 5. Paper trading и малый живой запуск (2-3 месяца)
- [ ] Минимум 1-2 месяца на демо, сравнение с бэктестом
- [ ] Деплой на VPS (Docker, автоперезапуск)
- [ ] Живой запуск на небольшую сумму, плечо 1-3x
- [ ] Ведение журнала: сделки, причины, отклонения от бэктеста
- [ ] Не менее 3-6 месяцев реальной статистики

**Результат:** реальная история результатов.

### Этап 6. Агентный слой (3-4 недели)
- [ ] Ежедневный и недельный отчёт простым языком
- [ ] Разбор новостей и событий, влияющих на открытые позиции
- [ ] Анализ закрытых сделок и поиск повторяющихся ошибок
- [ ] Объяснения в Telegram: «почему бот вошёл в ETH?»
- [ ] Жёсткие ограничения: агент без прав на торговлю, только читает и советует

### Этап 7. Продукт (параллельно или после этапа 5)
- [ ] Веб-дашборд: баланс, график доходности, список сделок
- [ ] Включение/выключение бота, настройки риска
- [ ] Мультипользовательность и безопасное хранение ключей (шифрование)
- [ ] Мониторинг, алерты о сбоях
- [ ] Тест с друзьями **только на демо-счёте**
- [ ] Юридическая проверка модели монетизации

## 7. Монетизация (от безопасной к рискованной)

1. **Софт как сервис.** Инструмент (бот, бэктестер, аналитика), пользователь сам подключает ключи и отвечает за решения. Регуляторно самый чистый вариант.
2. **Образовательный и аналитический контент.** Отчёты, разборы, исследования.
3. **Сигналы, копитрейдинг, управление чужими деньгами.** Самое доходное и самое зарегулированное. Во многих странах нужна лицензия. Не трогать без консультации юриста.

Нельзя обещать доходность. Главный маркетинговый актив — реальная проверяемая история собственной торговли.

## 8. Реалистичные ожидания

- Большинство торговых ботов не приносят прибыль после комиссий. Это нормально, и этапы 2-3 как раз нужны, чтобы это выяснить дёшево.
- «Пассивный» не значит «без присмотра»: за ботом нужно следить, рынок меняется, стратегии деградируют.
- Цель первого года: не «x2 в месяц», а стабильный результат при контролируемой просадке и отработанная система.
- Даже при скромной доходности проект даёт сильные навыки и портфолио: Python, данные, API, асинхронность, ML-валидация, агенты, деплой.
